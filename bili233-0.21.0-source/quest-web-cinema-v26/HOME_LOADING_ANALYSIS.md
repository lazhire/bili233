# 首页数量与加载问题分析（0.11.0）

## 代码中确认的风险

1. v8 的 client-layout.js 按 12 张 DOM 卡片划分页面，隐藏范围之外的卡片；reset/page 会把 body.visibility 设成 hidden。status 又根据标题、封面 complete、DOM 稳定时间决定显示。代码已有超时放行，因此不能简单断言它严格“必须收到 12 条才显示”，但把网页可见性与 DOM 内容状态绑定确实会产生隐藏/闪屏风险。
2. v8 把不包含当前有效视频卡片的子节点标记 q-source-empty；网站的骨架、尚未填充的卡片、其他功能区可能被归为空内容。隐藏节点也会改变网站自身懒加载所依赖的布局。
3. v15 已去除自定义分页。仍存在 onPageCommitVisible 只显示网页而不完成 native pagePublished 状态的问题：用户能看见页面，但底部加载提示仍等 onPageFinished；慢资源会造成持续转圈或错误的慢加载提示。
4. v15 广告检查每次先移除再添加隐藏属性；即使广告状态未变也反复修改 DOM。主题观察器对 class/style 变化递归检查子树，滚动或动画会扩大扫描工作量。

## 0.11.0 处理

- 首页继续使用原站卡片与滚动容器，新增分类导航和响应式网格样式。绝不按固定数量裁切、克隆视频卡片或隐藏 body；也不把数量用作 ready 判断。
- onPageCommitVisible 即结束 native 等待状态，onProgress=100 提供补充结束路径，onPageFinished 仍更新页面信息。首次显示只记录一次历史；慢加载超时后，后续进度事件不会重新拉起转圈。
- 广告过滤只针对独立卡片，状态不变不写 DOM；广告变回普通视频时恢复。不拦截混合推荐 API，不根据视频标题包含“广告”二字误删。
- class/style 变化只扫描目标节点；新插入的子树才递归分批扫描。
- 初次识别不到已知首页卡片时保持原网页；识别到后启用客户端式布局。可以在设置关闭布局立即恢复。
- 广告卡片默认过滤；游戏/会员购/下载入口、整个首页轮播各自独立开关，默认关闭。轮播开关会同时隐藏普通推荐，设置文案明确说明。

## 验证与限制

在独立临时 Edge 浏览器中使用本地构造的 DOM 测试，不访问真实账号。验证 0、1、11、12、13、21 张卡片；21 张含 2 条广告时展示 19 张；关闭过滤恢复 21 张；复用广告节点恢复普通内容；整批均为广告后追加普通视频仍显示；慢封面不阻止可见性；切换路由及关闭布局恢复原站样式。未观察到页面脚本错误。

这不是 Quest 真机或 B 站真实推荐接口测试，不能保证网络错误、风控、网站改版和原站自动加载行为均被修复。整批都是广告时允许列表为空；不会为了凑满数量不断自动请求。截图为合成测试页面，不代表真实视频内容或原生顶栏。
