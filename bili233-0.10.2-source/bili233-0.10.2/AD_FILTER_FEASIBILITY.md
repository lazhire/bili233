# 广告与推广过滤可行性检查

## 检查范围与结果

在连接的 Quest 3 上，对现有 WebView 的 B 站首页做只读 DOM 检查，未读取 Cookie、登录凭据或修改网络响应。此次页面有 21 个 .bili-video-card，其中 2 个包含文字恰为“广告”的 .bili-video-card__stats--text，且目标链接指向 cm.bilibili.com；所在外层为 .bili-feed-card。轮播 .carousel-item 中也发现 cm.bilibili.com 链接。首页内容随账户与刷新改变，数字只是本次样本。

## 可实施的方案

1. 明确标记的广告卡片：可靠性相对较高。按“广告”精确标签与 cm.bilibili.com 域名识别，隐藏对应外层 .bili-feed-card（或 .feed-card），不只隐藏里面的封面。普通推荐视频、自然搜索结果保留。用节流 MutationObserver 对新加载卡片增量判断，不等待固定视频数量，不重新分页，不刷新页面。DOM 隐藏只能去除显示，广告请求本身仍可能发生。
2. 游戏中心、会员购、下载 App 等独立导航或推广按钮：可提供单独开关隐藏明确入口。不要仅因出现“会员”“推广”等文字就删除内容，不拦截登录、付费播放提示与正常功能。
3. 轮播推广：中等可行性，轮播有内部索引、循环与占位逻辑。直接删除某张轮播可能产生空白；可以提供隐藏整个首页轮播的选项，或做专门的轮播处理，但隐藏整个轮播也会移除正常推荐。
4. 视频页面独立广告位：有稳定容器或外链标记时可以处理，需要再对视频/搜索/动态页面分别采样。此次只检查了首页，不应承诺所有页面均可去广告。
5. UP 主口播、植入、标题中软推广、直播画面内广告：属于视频内容，没有可靠 DOM 区分，不能仅靠网页 CSS 自动去除。需人工标记时间段或可信的内容数据，误判风险较高。
6. 网络广告拦截：不建议直接拦截整个 B 站 API 或 hdslb.com CDN；推荐响应可能混有普通内容，CDN 承载封面和视频。宽泛拦截会影响登录、首页和播放。只有确认是独立广告请求的路径，才适合另做可关闭的规则。

## 本次交付

0.10.2 仅改名与图标，广告过滤尚未启用。建议下一步添加可关闭的“过滤明确广告卡片”和“隐藏推广入口”选项；轮播单列开关，并提供恢复原网页的路径。规则属于网站 DOM 适配，需要随网站更新维护。
